# ASMRenderer 設計メモ

2026-06-05 の初期設計ディスカッションの記録。使い方・コマンドは README を参照。
ここには「何を作ろうとしているか」「何をなぜそう決めたか」「何がまだ決まっていないか」を残す。

## 背景・ゴール

YouTube の雑談配信 (1〜2 時間) の音声を、**話者が自分の周りを移動しながら
喋っているような ASMR 風バイノーラル音源**に変換するツールを作る。

イメージの参考: https://note.com/mishimahiaka/n/nad8c7d360bfe
(Audacity で手作業の疑似バイノーラル化。左右のフェードで移動感を出す手法。
本ツールはこれの自動化 + 高度化に相当する)

### 求める移動の性質 (要件)

- 高速に行き来するのではなく、**ある程度喋ったら右へ、正面へ、少し離れて…**と
  ランダムに周りを移動している感じ
- 移動は主に**会話の切れ目の前後**で起こる
  (一旦会話が切れる直前や、次に話し始めるタイミング)
- **喋りながら移動するタイミング**は ASMR 感の核なので必ず盛り込む
- **よそ見** (会話中に向こうの物を取るために向こうを向いて喋る) も適度に。
  ただし振り向きすぎは落ち着きがないので低頻度に
- 反復横跳びのような音源にはしない。なるべく自然に

## アーキテクチャ

```
音声 ─→ [separation] ─→ 声  ─→ [vad] ─→ [planner] ─→ プラン(JSON) ─→ [renderer] ─┐
       (--separate 時)  └─→ BGM ──────────────────────→ 静止ステレオミックス ──┴─→ 出力
```

3 段 (解析 → プランナー → レンダラー) に分け、**移動計画を JSON の中間成果物**
として吐くのが設計の肝。シードを変えて引き直す / 気に入らない移動だけ手で
編集して再レンダリング、というワークフローを可能にする。

### 座標系

- リスナーが原点、正面 0°、+90° が右、±180° が後ろ。距離はメートル
- プラン内の方位角は unwrap した連続値 (±180° を超えてよい) → 補間が単純になる
- `face`: 0 = こちら向き 〜 1 = 完全によそ見 (連続値)

## 決定事項と理由

| 決定 | 理由 |
|---|---|
| Python CLI (numpy/scipy/soundfile) | 音声処理ライブラリが最も充実。HRTF への発展も容易。2h 音源も現実的な処理時間 (5 分音源 ≈ 3 秒 → 2h でも 1〜2 分) |
| レンダラーは ITD/ILD + 時変フィルタのパラメトリック方式 (v0.1) | HRTF 畳み込みより実装が単純で、移動の滑らかさの調整が容易。前後の定位はやや弱いが、よそ見・距離は表現できる。HRTF は後から差し替えられる構造にした |
| 入力はローカル音声ファイルのみ | yt-dlp 連携は将来拡張。ツールの責務を明確に保つ |
| 音源分離は Demucs | 実用環境が Windows 11 のため。PyTorch の Windows + CUDA サポートが堅牢で、NVIDIA GPU があれば 2h 音源の分離が数分になる。audio-separator (onnxruntime 系) は依存が軽いが Windows GPU 対応が不安定なので見送り |
| BGM は -6dB で静止ミックス (デフォルト) | 移動する声が際立ち ASMR として自然。`--bgm-gain-db` で調整可能 |
| 分離は demucs CLI 経由のサブプロセス呼び出し | demucs のバージョン間 API 変動の影響を受けにくい |
| 分離結果は `<入力名>_stems/` にキャッシュ | 分離は重い (CPU で数十分)。一度分離すれば、シード変え・プラン調整のループは分離なしで高速に回せる |

### プランナーの設計 (要件 → パラメータ対応)

確率的状態機械。乱数はシード固定で決定論的。

- **会話の切れ目で移動**: VAD で検出したポーズ (≥0.5s) をトリガーに、
  dwell (25〜110s) 経過後に確率 0.6 で移動。タイミングにジッタを入れて
  「語尾を言いながら動き出す」「喋り出しと同時に到着」を再現
- **喋りながら移動** (`walk_talk`): 12s 以上の発話区間内に約 4 分に 1 回、
  5〜12 秒かけてゆっくり移動
- **よそ見** (`face_away`/`face_back`): 約 8 分に 1 回、よそ見同士は最低 30 秒
  間隔。位置移動と重ならない時間帯のみ
- **反復横跳び防止**: dwell 制約 + 背後に行きすぎたら正面方向へ戻るバイアス
- **距離**: 近距離 (0.45〜0.9m) を 55% で厚めにサンプル (ASMR なので)
- **揺らぎ**: 完全静止は不自然なので、±2.5° / ±3cm の遅い正弦波を常時重ねる

パラメータはすべて `PlannerParams` (planner.py) に集約。

### レンダラーの空間キュー

すべて `RendererParams` (renderer.py) に集約。

- **ITD**: 両耳への伝搬遅延を幾何計算し、可変フラクショナル遅延で適用。
  移動時に自然なドップラー風の揺らぎが出る (狙い通りの副作用)
- **ILD + 距離減衰**: 両耳それぞれへの 1/r ゲイン (近接時クランプあり)
- **頭部シャドウ**: 反対側の耳の高域減衰 (STFT ベースの時変フィルタ、hop=frame/2 の Hann OLA)
- **背後キュー**: 背後で 3〜8kHz を軽くディップ (簡易的な前後手がかり)
- **よそ見**: 高域カット + レベル低下。**残響は減らさない**ので「向こうを向いて
  喋っている」感が出る
- **距離感**: 合成 IR (指数減衰ノイズ、L/R 非相関) のルームリバーブ。
  遠いほど・よそ見ほど wet 増

## ハマりどころの記録

- **energy VAD のノイズフロア推定**: 当初「下位 10 パーセンタイル + 9dB」で
  実装したが、雑談配信はほぼ喋りっぱなしで無音が 1 割を切るため破綻した
  (下位 10% も発話フレームになる)。**「発話レベル (p95) − 20dB」の上から方式**に
  変更して解決。なお `--separate` を使えば声 stem には BGM がいないので
  energy VAD で十分になり、silero VAD の必要性は薄れた
- **Demucs の出力は 44.1kHz 固定** (htdemucs モデル準拠)。入力が 48kHz でも
  `--separate` 時の出力は 44.1kHz になる

### Windows 移行時の手順

```sh
git clone <このリポジトリ>
cd ASMRenderer
uv sync                            # 本体 (依存は numpy/scipy/soundfile のみ)
uv run pytest                      # 動作確認
# 音源分離を使う場合 (NVIDIA GPU があるなら CUDA 版 torch を先に):
uv pip install torch --index-url https://download.pytorch.org/whl/cu124
uv pip install -e '.[separate]'
```
